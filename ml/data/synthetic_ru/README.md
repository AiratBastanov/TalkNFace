# Russian interpretation corpus v1

Project-authored synthetic supervision for the **existing** `PlayerMoveInterpretation` contract. This is an offline R&D fixture, not a production scenario inventory or trained model. License status: **NOT_ASSIGNED**. No new dataset license is granted.

The corpus contains 10,000 records: 8,000 TRAIN, 1,000 DEV, 1,000 locked INTERNAL_TEST. A separate 304-record tuning evaluation lives in `evals/local-qwen/dev-ru-v1.json` and explicitly sets `TUNING_EVAL_ALLOWED=true`. The 180-entry context registry contains only public interpretation information. Canonical JSONL uses `contextId`; expanded prompts are never committed.

From the repository root, using the existing environment:

```powershell
.venv-ml/Scripts/python.exe ml/data/synthetic_ru/generate.py --check
.venv-ml/Scripts/python.exe ml/data/synthetic_ru/validate.py
node ml/data/synthetic_ru/verify_contract.mjs
.venv-ml/Scripts/python.exe -m unittest discover -s ml/data/synthetic_ru -p test_dataset.py -v
.venv-ml/Scripts/python.exe ml/data/synthetic_ru/compile_sft.py --split train --output .tmp/train-sft.jsonl
```

The compiler writes exclusively to a **new** file below `.tmp/`. It offers TRAIN/DEV only; INTERNAL_TEST is unavailable as a training export. Each record has conversational `prompt` and `completion` lists compatible with [TRL's documented prompt-completion format](https://huggingface.co/docs/trl/sft_trainer#expected-dataset-type-and-format). No TRL dependency is installed or imported. A future trainer must apply the local Qwen template with `enable_thinking=False` and verify completion loss boundaries. Do not truncate a target JSON object to fit a sequence limit.

`generate.py` constructs semantic cases and targets before rendering Russian language. `--check` reproduces and byte-compares the data. An existing `internal_test.jsonl` with different generated bytes cannot be overwritten. Candidate builds can be qualified in workspace `.tmp/`; the accepted INTERNAL_TEST is frozen on materialization in this directory. Future work must use DEV for iteration, not modify INTERNAL_TEST or A01–A16.

For an independent audit rerun, write reports to scratch:

```powershell
.venv-ml/Scripts/python.exe ml/data/synthetic_ru/audit.py --output .tmp/synthetic-audit.json
.venv-ml/Scripts/python.exe ml/data/synthetic_ru/token_stats.py --output .tmp/synthetic-tokens.json
```

The audit reads only the frozen holdout's `id`/`text` projection for exclusion checks, never its expected labels or model outputs. It never makes inference calls. Token statistics use the existing tokenizer offline; an audit hook refuses weight-file access and network connections.
