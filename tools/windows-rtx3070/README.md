# RTX 3070: короткая проверка Qwen3-4B на другом Windows-компьютере

Это инструкция для человека **без Codex и опыта машинного обучения**. Нужны обычный PowerShell, интернет и Windows x86-64 с RTX 3070 8 ГБ. Администратор для запуска проекта не нужен. Ничего отправляться с компьютера автоматически не будет.

Проверка делает **только два обновления небольшого адаптера**. Это не обучение всей модели и не оценка качества. Предыдущая проверка q/v-r8 на RTX 2060 остановилась **до загрузки модели** из-за занятости видеопамяти: эта архитектура ещё не проверена обучением и не объявлена неудачной по памяти.

Понадобятся:

- Windows 10/11 x64; рекомендуем Windows 11. Не WSL и не Docker.
- GPU класса 8192 MiB; скрипт допускает небольшое расхождение показаний, но не карту 6 ГБ. Название может иметь префикс производителя; фактическое имя сохраняется. CUDA-проверка требует compute capability 8.6.
- **12 GiB свободной физической RAM** перед запуском. 32 ГБ всего рекомендуются, но не обязательны, если свободной памяти достаточно.
- **30 GiB свободного места перед скачиванием модели**. Лучше начать с 40–45 GiB: окружение и пакеты тоже занимают место. Перед самим экспериментом нужно ещё 5 GiB свободного места.
- Интернет для Git, пакетов и оригинальной модели размером около 8 ГБ. Исходные внешние датасеты не нужны.

Команды ниже выполняйте **по одной**. После красного `FAILED` остановитесь и прочитайте причину. Не запускайте следующую фазу «на всякий случай», кроме упаковки результата `05`. Окно PowerShell не закрывайте во время работы скрипта. При загрузке больших пакетов выполнение может занять несколько минут; скрипт печатает состояние и путь к логам.

## 1. Проверить NVIDIA

Откройте обычный **Windows PowerShell**, не «от имени администратора»:

```powershell
nvidia-smi
```

В таблице должна быть ваша RTX 3070 и около `8192 MiB` памяти. Если команда не найдена или сообщает ошибку драйвера, сначала вручную проверьте/обновите драйвер с [официального сайта NVIDIA](https://www.nvidia.com/Download/index.aspx). Скрипты драйвер не меняют. Строка `CUDA Version` в этой таблице описывает возможности драйвера; она не обязана совпадать с CUDA 12.6 внутри PyTorch. **CUDA Toolkit устанавливать не нужно.**

## 2. Установить Git, если его нет

```powershell
git --version
```

Если команда отсутствует, откройте официальный сайт:

```powershell
Start-Process 'https://git-scm.com/install/windows'
```

Установите Git for Windows x64 обычным официальным установщиком для своего пользователя. Если установка недоступна по правилам вашего компьютера, обратитесь к его владельцу; не обходите ограничения. Репозиторию не нужен доступ на запись в GitHub и не нужны ваши GitHub-токены.

## 3. Установить Python 3.12.10 x64, если его нет

```powershell
py -3.12 --version
```

Для точного воспроизведения используем **Python 3.12.10**, а не другую основную или дополнительную версию. Если команда не работает или показывает другую patch-версию, откройте официальный выпуск:

```powershell
Start-Process 'https://www.python.org/downloads/release/python-31210/'
```

Выберите **Windows installer (64-bit)**. Установите для текущего пользователя, оставьте `pip` и Python Launcher (`py`). Не выбирайте установку для всех пользователей / административную установку launcher. Скрипты проекта не устанавливают Python в систему и не меняют постоянный PATH. Не удаляйте чужие Python-окружения.

## 4. Открыть новое окно PowerShell

Закройте старое окно, откройте новое и проверьте:

```powershell
git --version
py -3.12 --version
```

Python должен вывести `Python 3.12.10`.

Можно клонировать на другой диск, где достаточно места. Имя пользователя и абсолютный путь не важны: все скрипты находят корень относительно своего файла. Папки с пробелами поддерживаются. Не редактируйте Python-файлы и не переносите `AlagDatasets` с компьютера владельца проекта.

Если GitHub сообщает, что доступа к репозиторию нет, попросите владельца предоставить **доступ на чтение**. Доступ на запись не нужен. Не помещайте пароль или токен в команды, файлы проекта или отправляемый архив.

## 7. Предварительная проверка — только чтение

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\windows-rtx3070\00-preflight.ps1
```

Проверяются Windows, GPU 0, объём и свободная VRAM, драйвер, RAM и место на диске. Этот скрипт ничего не устанавливает и не записывает. `ExecutionPolicy Bypass` действует только для запускаемого процесса; глобальная политика не изменяется.

## 8. Создать изолированное окружение

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\windows-rtx3070\01-setup-python-env.ps1
```

Будет создана только папка `.venv-qlora-remote` внутри репозитория. Активировать окружение вручную не надо. Все дальнейшие команды используют его Python напрямую.

Точные основные версии: torch **2.14.0+cu126**, Transformers **5.17.0**, bitsandbytes **0.50.2**, PEFT **0.21.0**, TRL **1.13.0**, accelerate **1.15.0**, datasets **5.0.1**, safetensors **0.8.0**, psutil **7.2.2**. Все зависимости также закреплены по версиям и SHA-256 в `requirements*.txt` / `runtime-lock.json`.

PyTorch ставится из [официального CUDA 12.6 индекса](https://download.pytorch.org/whl/cu126/torch/); остальные колёса — из PyPI. Разрешены только готовые бинарные wheels с проверкой хеша. Исходная сборка запрещена. Если нужное колесо недоступно, **не выбирайте другую версию** и не ставьте Visual Studio/компилятор: отправьте результат владельцу.

Скрипт сохраняет `pip --version`, `pip freeze --all`, `pip check`, версии и происхождение wheels. Затем проверяет CUDA и делает **маленькую NF4-операцию на GPU**, без Qwen, обратного прохода или обновления параметров. Успешного `import bitsandbytes` недостаточно. Если CUDA не работает, исправляется драйвер вручную, а не установкой CUDA Toolkit.

## 9. Скачать и проверить оригинальный Qwen3-4B

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\windows-rtx3070\02-download-and-verify-model.ps1
```

Источник — [официальный `Qwen/Qwen3-4B`](https://huggingface.co/Qwen/Qwen3-4B), зафиксированный revision `1cfa9a7208912126459214e8b04321603b3df60c`. Используется `huggingface_hub.snapshot_download`, без токена и входа в аккаунт. Скачиваются только оригинальные safetensors, конфигурация, индекс и файлы токенизатора. Никаких GGUF, Base или другой размерности.

Модель попадёт в `AlagModels\Qwen3-4B`. Проверяются SHA-256 всех необходимых файлов, включая три шардa:

```text
model-00001-of-00003.safetensors 328a91d3122359d5547f9d79521205bc0a46e1f79a792dfe650e99fc2d651223
model-00002-of-00003.safetensors 6cd087b316306a68c562436b5492edbcf6e16c6dba3a1308279caa5a58e21ca5
model-00003-of-00003.safetensors e4bf436957184f4eeb86a80e9db394503f1f56446b2e6b7edeac5b81470f4ca1
```

Уже существующая полностью проверенная модель повторно не скачивается. После сетевого обрыва можно повторить `02` для недостающих файлов. При несовпадении хеша скрипт останавливается и не перезаписывает файл. Не меняйте хеши и не удаляйте модель автоматически: отправьте диагностику владельцу.

## 10. Освободить GPU и RAM вручную

Закройте игры, OBS, тяжёлые вкладки браузера и другие приложения, использующие GPU. Скрипты не завершают чужие процессы. Перед экспериментом нужны минимум **7168 MiB свободно по nvidia-smi** и **6656 MiB свободно по CUDA**, плюс 12 GiB свободной RAM. Это заранее объявленные пороги старта для 8-ГБ компьютера; они не доказывают, что обучение уже помещается.

## 12. Один эксперимент, два обновления

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\windows-rtx3070\04-run-targeted-memory-smoke.ps1
```

Это **единственный** скрипт, запускающий обучение. Перед загрузкой выполняется свежая проверка ресурсов. Если он пишет:

```text
ACTION REQUIRED: close GPU-heavy applications and rerun script 04.
```

закройте приложения вручную и повторите `04`, **только если загрузка модели ещё не началась и нет активного `campaign-started.json`**. Гонка внешней занятости GPU до загрузки сохраняется отдельно и не расходует единственный эксперимент. После начала загрузки модели маркер сохраняется при любом исходе. Не удаляйте маркер для повторного запуска.

Фиксированная конфигурация: q_proj/v_proj, r=8, alpha=16, dropout=0.05; **2 949 120** trainable parameters, **72 A + 72 B**; NF4 double quant, FP16, CUDA:0; Transformers checkpoint activation offload в pinned host RAM; batch 1, accumulation 4, два обновления paged_adamw_8bit, learning rate 2e-4. База заморожена, CPU-offload весов и `device_map="auto"` не используются.

Независимый монитор читает RAM/GPU примерно каждые 200 мс. Если свободная RAM опустится ниже 6 GiB или pagefile вырастет более чем на 256 MiB, останавливается только собственный worker. Ограничения: загрузка 300 с, отдельный forward/backward 600 с, кампания 1800 с, свежий reload 600 с. Watchdog не увеличивается после ошибки.

После успешных обновлений сохраняется только адаптер в `AlagModels\adapters\rtx3070-targeted-smoke\1024`. Весь обучающий процесс завершается. Новый процесс заново загружает базу и адаптер, проверяет его хеши и делает один finite-logit forward на неиспользованной TRAIN-записи. Генерации и оценки качества нет.

Исходы:

- `RTX3070_TARGETED_LORA_MEMORY_SMOKE_PASS`: все проверки успешны, peak allocated ниже CUDA capacity, на обеих границах обновлений свободно **≥512 MiB CUDA**.
- `...PASS_TIGHT_MEMORY`: все остальные проверки успешны, минимум свободной CUDA памяти **≥256, но <512 MiB**. Это тесный запас, а не комфортный PASS.
- `...MEMORY_FAIL`: OOM, выход за capacity, свободно <256 MiB либо нарушена безопасность RAM/pagefile. Следующий шаг — `QWEN3_4B_LARGER_GPU_TRAINING_ARCHITECTURE`.
- `...GPU_ENVIRONMENT_BLOCKED`, `...RUNTIME_BLOCKED`, `...MODEL_INTEGRITY_FAIL`, `...FAIL`: причина будет в `RESULT.txt` и логах. Не меняйте настройки самостоятельно.

CUDA reserved записывается отдельно и не объявляется физически занятой VRAM. Даже PASS проверяет только конфигурацию 1024 с фактическим максимумом выбранных записей **974** (максимум первых восьми **962**). Он не доказывает, что помещаются 1421/1536 токенов. После PASS рекомендован только отдельный `RTX3070_TARGETED_LORA_1536_ENVELOPE_SMOKE`; запускать его сейчас нельзя. Никаких rank-4, 768, LoRA-FA, иных оптимизаторов или повторного обучения после неудавшейся кампании.

## Если что-то не получилось

1. Не переходите к обучению при проваленной установке, проверке хешей или подготовке.
2. Не меняйте версии пакетов, learning rate, rank, длины или выборку.
3. Не ставьте CUDA Toolkit, Visual Studio, WSL или Docker; не отключайте защиту, TLS, firewall и не меняйте pagefile/реестр.
4. Выполните `05` и отправьте ZIP. Если Python не установлен совсем, `05` создаст минимальный диагностический архив средствами PowerShell.
5. Если активный контролёр ещё работает, дождитесь его окончания. После аварийного выхода упаковка допускается, но повторная кампания запрещена.

Для просмотра действий **без изменений на компьютере** добавьте `-DryRun` к любой команде `00`–`05`. Такой вывод не является успешной проверкой GPU или обучением.

Официальные основания: [PyTorch](https://pytorch.org/get-started/locally/), [pip binary-only / hash checking](https://pip.pypa.io/en/stable/cli/pip_install/), [Hugging Face snapshot download](https://huggingface.co/docs/huggingface_hub/guides/download), [bitsandbytes Windows/CUDA](https://huggingface.co/docs/bitsandbytes/installation). Используются замороженные версии проекта, а не автоматически выбранные «последние».
