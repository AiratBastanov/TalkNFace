# Арена переговоров

Реализованы **G0 — runtime foundation, G1 — deterministic core, G2 — игровой S1 без AI**. Администратор публикует проверенную версию «Закупки к запуску», игрок читает брифинг, ведёт переговоры через выбор действий и получает результат с разбором по событиям. SQLite сохраняет версию, состояние и диалог после обновления страницы и перезапуска приложения. Повтор создаёт чистую попытку той же ситуации.

Это локальный **демо-режим без AI** для практики начинающих закупщиков и руководителей. AI, свободный текст, динамическая генерация сценариев, S2 в интерфейсе, полный педагогический разбор, авторизация пользователей и публичное развёртывание **не реализованы**. Числа описывают учебную модель, а не оценку реальных переговорных компетенций. **G3 не начат и автоматически не разрешён.**

## Runtime и установка

Проверенный runtime: **Node 24.21.0, npm 11.19.0**, Windows x64. Требуется Node **24.x**; Node 22 не является certified G0 runtime и отклоняется проверкой проекта. Версия закреплена в `.node-version`. Для первоначального `npm ci` нужен доступ к npm registry и GitHub Releases (SQLite prebuilt); после установки приложение запускается локально без внешних сервисов.

Менять системный Node не требуется. Подходит официальный portable ZIP внутри `.tools/` (каталог игнорируется Git):

- [Node 24.21.0 Windows x64](https://nodejs.org/download/release/v24.21.0/node-v24.21.0-win-x64.zip)
- [Официальный SHASUMS256](https://nodejs.org/download/release/v24.21.0/SHASUMS256.txt)

Перед распаковкой сравните SHA-256 ZIP с его строкой в официальном SHASUMS256. Проверенный hash: `158f7685b44de51f6c0df1d153526cbcd3e1bc739a8dfc607721cef75de9e541`.

Для уже распакованного portable runtime, **из корня проекта в PowerShell**:

```powershell
$node24 = (Resolve-Path '.tools\node-v24.21.0-win-x64').Path
$env:PATH = "$node24;$env:PATH"
& "$node24\node.exe" --version
& "$node24\npm.cmd" --version
& "$node24\npm.cmd" ci
```

Это меняет PATH только текущего процесса PowerShell и его дочерних процессов. Системная установка остаётся прежней. Используйте `npm.cmd`, если политика PowerShell блокирует `npm.ps1`; менять execution policy не нужно.

При выбранном Node 24 стандартные команды из корня проекта:

```text
npm ci
npm run dev
```

Dev: http://127.0.0.1:5173 — Vite с обновлением frontend; Fastify работает на порту 3000. Vite проксирует `/api`, `/health` и `/ready` на backend. После изменения backend остановите dev через Ctrl+C и запустите снова. CORS не нужен. В PowerShell команды эквивалентны `& "$node24\npm.cmd" run dev` и остальным командам ниже.

## Production и проверки

```text
npm run typecheck
npm run build
npm test
npm run smoke
npm run test:e2e
npm start
```

`npm test` проверяет **реальные артефакты сборки**, поэтому перед ним нужен `npm run build`. `npm run smoke` запускает два последовательных production-процесса, проверяет HTTP и сохранение sentinel после restart, затем закрывает их. Временная SQLite находится в `.tmp/` и удаляется; `data/arena.sqlite` smoke не затрагивает.

Сборка включает `@arena/contracts`, `@arena/domain` и `@arena/scenarios`; typecheck предварительно собирает их общие декларации. [Таблицы моделей и golden traces G1](docs/gates/evidence/G1_MODEL_AUDIT.json) сохранены как неизменённое основание G2.

`npm run test:e2e` требует установленный **Google Chrome** и использует проектный `@playwright/test@1.63.0`. Браузер скачивать не нужно: `channel: chrome` запускает отдельный процесс/профиль. Проверки используют настоящий `npm start`, production build, отдельную SQLite и viewport 360/390/1280. Они проверяют публикацию, два разных исхода, принятие оферты, refresh, restart, replay и повтор отправки после потери ответа. Тестовый stdin-адаптер вызывает штатный SIGINT handler для чистой остановки Windows-процесса. Отчёты и снимки сохраняются в `.tools/`; рабочая БД не затрагивается. Полная проверка ограничена 180 секундами, один тест — 90 секундами.

`npm start` всегда включает production-режим. Один Node-процесс Fastify обслуживает React/Vite build и API с одного origin:

- http://127.0.0.1:3000/ — вход игрока и опубликованные ситуации.
- http://127.0.0.1:3000/admin — просмотр эталона и публикация S1.
- http://127.0.0.1:3000/health — `200 {"status":"ok"}`; liveness, без путей и конфигурации.
- http://127.0.0.1:3000/ready — `200 {"status":"ready"}` после реального SQLite-запроса, либо `503 {"status":"not_ready"}`.

Неизвестные `/api/*` и отсутствующие assets возвращают JSON 404. HTML fallback применяется только к GET/HEAD-навигации с `Accept: text/html` вне служебных путей. Ctrl+C/SIGTERM закрывает HTTP-сервер и SQLite. Локальный parent-process также может вызвать тот же shutdown через IPC; HTTP-метода остановки нет.

## Пройти S1 без ключей

1. Выполните `npm run build`, затем `npm start` и откройте `/admin`.
2. Просмотрите роли, цель, ограничения и переменные. Нажмите **«Опубликовать S1»**. Повторная публикация не создаёт копий одной версии.
3. Перейдите ко входу игрока, выберите ситуацию, прочитайте брифинг и нажмите **«Начать переговоры»**.
4. Выбирайте вопросы, признание известных фактов, аргументы, условия предложения, давление или выход. Произвольный текст не распознаётся. Пакет содержит цену, поставку и предоплату; каждое значение выбирается явно, без округления. Перед предложением, принятием и выходом требуется подтверждение.
5. На результате откройте ссылки на ходы, сравните сделку со своей целью и альтернативой. **«Повторить ту же ситуацию»** создаёт новую сессию той же версии без переноса фактов и истории.

Короткий проверенный путь: вопрос **«Возможности поставки»** → вопрос **«Условия оплаты»** → признать факт о предоплате на сырьё → аргумент **«Учесть экономию на разделении партии»** → предложить **95 / 40% на день 7, остаток на день 14 / 50%**. Результат — «Цель достигнута».

Контрастный путь: предложить **90 / всё на день 7 / 0%**, затем четыре раза выбрать давление с тоном **«Личная угроза»**. После предупреждения оппонент завершит разговор без сделки. Это один из проверенных путей, не обязательная последовательность: можно предлагать условия до вопросов, принимать действующую оферту, заключать частичную или невыгодную сделку, выходить по собственной инициативе.

Адрес `/session/:id` восстанавливает попытку из SQLite. Вход игрока также сохраняет ссылку на последнюю попытку в этом браузере. После потери ответа кнопка **«Повторить отправку»** использует тот же requestId; при конфликте вкладок интерфейс загружает актуальную сессию. Подтверждение брифинга открывает диалог, но само не расходует ход G1.

## Конфигурация и SQLite

Запуск **не требует AI credentials**. Без `.env` используются безопасные defaults. При необходимости скопируйте `.env.example` в `.env`; настоящий `.env` игнорируется Git. Переменные процесса имеют приоритет над файлом.

| Переменная | Default / назначение |
|---|---|
| `NODE_ENV` | `development`; dev/start выбирают соответствующий режим явно |
| `HOST` | `127.0.0.1` |
| `PORT` | `3000`, целое 1–65535 |
| `DATABASE_PATH` | `./data/arena.sqlite`; относительный путь считается от корня проекта, абсолютный также допустим |

Каталог БД создаётся автоматически. SQLite включает foreign keys, busy timeout 5000 ms и WAL. До готовности сервера применяются миграции **1 → 2**: G0 `foundation_metadata` сохраняется, G2 добавляет `scenario_versions`, `sessions`, `turns`. Startup не очищает данные; неизвестная будущая версия схемы вызывает отказ. Сценарий хранится полностью на сервере и закреплён за сессией; опубликованную версию нельзя обновить или удалить. Повреждённое состояние не исправляется автоматически.

Каждый ход проходит G1 и сохраняется вместе с ответом в одной immediate-транзакции. Совпадающий requestId и body возвращают прежний ответ; другой body с тем же ID или устаревшая revision дают 409. Невозможная, но корректно заполненная оферта расходует ход и возвращает обычный ответ с отказом. Неверная структура запроса даёт 400, неприменимое действие — 422 без хода. Старый диалог читается из сохранённых текстов. Полная спецификация API и схемы — в G2 receipt.

Драйвер закреплён на **better-sqlite3 12.11.1**, SQLite **3.53.2**. Stable 13.0.3 загрузился при первой установке, но вызвал node-gyp при чистом `npm ci`; разрешённый fallback 12.11.1 прошёл обе установки с официальным Windows prebuilt. Системные build tools не нужны для проверенного пути. Его транзитивный `prebuild-install` выдаёт предупреждение об окончании поддержки; подробности сохранены в receipt.
