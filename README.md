# Арена переговоров

Реализованы **G0 — runtime foundation, G1 — deterministic core, G2 — игровой S1 без AI**, а также **guided-компонент G7: S2 «Срочная задача и нагрузка»** и **детерминированный компонент G6: разбор действий по сохранённым доказательствам**. Добавлен детерминированный компонент G5: администратор настраивает контекст S1/S2, сохраняет черновик, проверяет достижимость, просматривает брифинг и явно публикует отдельную версию; игрок читает брифинг, ведёт переговоры через выбор действий и получает результат с наблюдениями по событиям. SQLite сохраняет версию, состояние и диалог после обновления страницы и перезапуска приложения. Повтор создаёт чистую попытку той же ситуации.

Это локальный **демо-режим без AI** для практики начинающих закупщиков и руководителей. Администратор входит по паролю владельца; игрок получает серверную сессию без регистрации и видит только свои попытки. Изменения защищены CSRF и проверкой Origin. [Граница доступа G8](docs/gates/APP_G8_ACCESS_BOUNDARY_01.md). Свободный текст, live AI, AI-генерация и произвольный редактор сценариев, AI-объяснение разбора и публичное развёртывание **не реализованы**. Числа описывают учебную модель, а не оценку реальных переговорных компетенций. **Полные G5/G6/G7/G8 и FULL_AI_MVP_PASS не заявляются.** [Настройка контекста G5](docs/gates/APP_G5_CONTEXT_CONFIGURATION_01.md). [Детерминированный разбор G6](docs/gates/APP_G6_DETERMINISTIC_FEEDBACK_01.md). [Исторический PARTIAL-аудит и проверка S2](docs/gates/APP_AUDIT_AND_QWEN_INDEPENDENT_SLICE_01.md).

Workspace-list явно включает только пакеты приложения. Незавершённый `packages/ai` сохранён как исходный scaffold вне app-workspaces: его provider SDK отсутствует в принятом lockfile и для guided-режима не устанавливается. Frozen contracts/context/prompt и training workflow не изменены.

## Runtime и установка

Проверенный runtime: **Node 24.21.0, npm 11.19.0**, Windows x64. Требуется Node **24.x**; Node 22 не является certified G0 runtime и отклоняется проверкой проекта. Версия закреплена в `.node-version`. Для первоначального `npm ci` нужен доступ к npm registry и GitHub Releases (SQLite prebuilt); после установки приложение запускается локально без внешних сервисов.

Менять системный Node не требуется. Подходит официальный portable ZIP внутри `.tools/` (каталог игнорируется Git):

- [Node 24.21.0 Windows x64](https://nodejs.org/download/release/v24.21.0/node-v24.21.0-win-x64.zip)
- [Официальный SHASUMS256](https://nodejs.org/download/release/v24.21.0/SHASUMS256.txt)

Перед распаковкой сравните SHA-256 ZIP с его строкой в официальном SHASUMS256. Проверенный hash: `158f7685b44de51f6c0df1d153526cbcd3e1bc739a8dfc607721cef75de9e541`.

Для уже распакованного portable runtime, **из корня проекта в PowerShell**:

```powershell
$node24 = (Resolve-Path '.tools\node-v24.21.0-win-x64').Path
$env:PATH = "$node24;$env:PATH"
& "$node24\node.exe" --version
& "$node24\npm.cmd" --version
& "$node24\npm.cmd" ci
```

Это меняет PATH только текущего процесса PowerShell и его дочерних процессов. Системная установка остаётся прежней. Используйте `npm.cmd`, если политика PowerShell блокирует `npm.ps1`; менять execution policy не нужно.

При выбранном Node 24 стандартные команды из корня проекта:

```text
npm ci
npm run dev
```

Dev: http://127.0.0.1:5173 — Vite с обновлением frontend; Fastify работает на порту 3000. Vite проксирует `/api`, `/health` и `/ready` на backend. После изменения backend остановите dev через Ctrl+C и запустите снова. CORS не нужен. В PowerShell команды эквивалентны `& "$node24\npm.cmd" run dev` и остальным командам ниже.

Для dev задайте `APP_ORIGIN=http://127.0.0.1:5173` (при отсутствии переменной dev выбирает этот адрес сам). Для production demo используется `http://127.0.0.1:3000`. Не смешивайте `localhost` и `127.0.0.1`: Origin проверяется точно.

## Production и проверки

```text
npm run typecheck
npm run build
npm test
npm run smoke
npm run test:e2e
npm start
```

`npm test` проверяет **реальные артефакты сборки**, поэтому перед ним нужен `npm run build`. `npm run smoke` запускает два последовательных production-процесса, проверяет HTTP и сохранение sentinel после restart, затем закрывает их. Временная SQLite находится в `.tmp/` и удаляется; `data/arena.sqlite` smoke не затрагивает.

Сборка включает `@arena/contracts`, `@arena/domain` и `@arena/scenarios`; typecheck предварительно собирает их общие декларации. [Таблицы моделей и golden traces G1](docs/gates/evidence/G1_MODEL_AUDIT.json) сохранены как неизменённое основание G2.

`npm run test:e2e` требует установленный **Google Chrome** и использует проектный `@playwright/test@1.63.0`. Браузер скачивать не нужно: `channel: chrome` запускает отдельный процесс/профиль. Проверки используют настоящий `npm start`, production build, отдельную SQLite и viewport 360/390/1280. Они проверяют публикацию, два разных исхода, принятие оферты, refresh, restart, replay и повтор отправки после потери ответа. Тестовый stdin-адаптер вызывает штатный SIGINT handler для чистой остановки Windows-процесса. Отчёты и снимки сохраняются в `.tools/`; рабочая БД не затрагивается. Полная проверка ограничена 180 секундами, один тест — 90 секундами.

`npm start` всегда включает production-режим. Один Node-процесс Fastify обслуживает React/Vite build и API с одного origin:

- http://127.0.0.1:3000/ — вход игрока и опубликованные ситуации.
- http://127.0.0.1:3000/admin — вход администратора, затем настройка контекста, черновик, проверка, предпросмотр и публикация; ниже сохранён быстрый выбор исходных эталонов. Кнопка «Выйти» отзывает доступ.
- http://127.0.0.1:3000/health — `200 {"status":"ok"}`; liveness, без путей и конфигурации.
- http://127.0.0.1:3000/ready — `200 {"status":"ready"}` после реального SQLite-запроса, либо `503 {"status":"not_ready"}`.

Неизвестные `/api/*` и отсутствующие assets возвращают JSON 404. HTML fallback применяется только к GET/HEAD-навигации с `Accept: text/html` вне служебных путей. Ctrl+C/SIGTERM закрывает HTTP-сервер и SQLite. Локальный parent-process также может вызвать тот же shutdown через IPC; HTTP-метода остановки нет.


## Настроить контекст и пройти демонстрацию G5

В уже собранном worktree используйте точную PowerShell-команду запуска владельца ниже; URL — http://127.0.0.1:3000/admin.

1. В «Настроить контекст» оставьте сферу **«Промышленные закупки»**, сложность **«Обычная»**, роль **«Директор продаж»**. Выберите тему **«Плановая поставка»**, тон **«Дружелюбный»**, цель **«Доходность сделки»**.
2. Нажмите **«Сохранить черновик» → «Подобрать и проверить сценарий» → «Предпросмотр»**. Проверьте брифинг, отметьте явное одобрение и нажмите **«Опубликовать» → «Начать настроенные переговоры»**.
3. В брифинге выберите целевую границу и подтвердите свою альтернативу кнопкой **«Сохранить подготовку»**, затем начните переговоры.
4. Спросите о поставке → признайте экономию на разделении партии → используйте соответствующий аргумент → спросите об оплате → предложите **95 / 40% на день 7, остаток на день 14 / 50%**. Проверенный результат: полезность 64, полная цель достигнута.
5. Откройте доказательство в разборе G6: ссылка ведёт к точной сохранённой реплике. **«Повторить ту же ситуацию»** создаёт новую попытку на той же опубликованной версии.

Для S2 выберите сферу **«Управление командой»** и заново укажите тему **«Срочный проект»**, роль **«Руководитель группы»**, цель **«Выполнить полный объём»**. Проверен вариант «Повышенная» / «Дружелюбный» с обычным S2 путём ниже.

Один локальный черновик сохраняется на сервере. Любая правка отменяет прошлое одобрение; старая вкладка не перезапишет новую ревизию. После потерянного ответа публикацию можно повторить той же кнопкой без дубликата. Смена сферы очищает зависимые выборы. Исходные S1/S2 и прежние сессии остаются доступны.

Допустимы не все сочетания: например, **«Переприоритизация без помощника»** при фиксированной цели игрока 45 отклоняется. Для S1 менеджер с целью «Доходность сделки» не достигает цели игрока 62. Валидатор не добавляет ресурсы и не понижает цель. Это подбор производных reference-конфигураций без модели; будущие AI-генерация и проверка Qwen для новых контекстов остаются отдельными задачами.

## Пройти S1 без ключей

1. Выполните `npm run build`, настройте пароль по инструкции ниже, затем запустите приложение и войдите на `/admin`.
2. Просмотрите роли, цель, ограничения и переменные. Нажмите **«Опубликовать S1»**. Повторная публикация не создаёт копий одной версии.
3. Перейдите ко входу игрока, выберите ситуацию, прочитайте брифинг, явно выберите цель и подтвердите свою альтернативу кнопкой **«Сохранить подготовку»**, затем нажмите **«Начать переговоры»**. Без записи подготовки общий балл не будет показан.
4. Выбирайте вопросы, признание известных фактов, аргументы, условия предложения, давление или выход. Произвольный текст не распознаётся. Пакет содержит цену, поставку и предоплату; каждое значение выбирается явно, без округления. Перед предложением, принятием и выходом требуется подтверждение.
5. На результате откройте ссылки на ходы, сравните сделку со своей целью и альтернативой. **«Повторить ту же ситуацию»** создаёт новую сессию той же версии без переноса фактов и истории.

Короткий проверенный путь: вопрос **«Возможности поставки»** → вопрос **«Условия оплаты»** → признать факт о предоплате на сырьё → аргумент **«Учесть экономию на разделении партии»** → предложить **95 / 40% на день 7, остаток на день 14 / 50%**. Результат — «Цель достигнута».

Контрастный путь: предложить **90 / всё на день 7 / 0%**, затем четыре раза выбрать давление с тоном **«Личная угроза»**. После предупреждения оппонент завершит разговор без сделки. Это один из проверенных путей, не обязательная последовательность: можно предлагать условия до вопросов, принимать действующую оферту, заключать частичную или невыгодную сделку, выходить по собственной инициативе.

Адрес `/session/:id` восстанавливает попытку из SQLite. Вход игрока также сохраняет ссылку на последнюю попытку в этом браузере. После потери ответа кнопка **«Повторить отправку»** использует тот же requestId; при конфликте вкладок интерфейс загружает актуальную сессию. Подтверждение брифинга открывает диалог, но само не расходует ход G1.

## Конфигурация и SQLite

Запуск **не требует AI credentials**. Без `.env` используются безопасные defaults. При необходимости скопируйте `.env.example` в `.env`; настоящий `.env` игнорируется Git. Переменные процесса имеют приоритет над файлом.

| Переменная | Default / назначение |
|---|---|
| `NODE_ENV` | `development`; dev/start выбирают соответствующий режим явно |
| `HOST` | `127.0.0.1` |
| `PORT` | `3000`, целое 1–65535 |
| `DATABASE_PATH` | `./data/arena.sqlite`; относительный путь считается от корня проекта, абсолютный также допустим |
| `ACCESS_PROFILE` | `local`: только loopback HTTP; `public`: явно заданный HTTPS origin, Secure cookie |
| `APP_ORIGIN` | `http://HOST:PORT` в local production; для Vite dev `http://127.0.0.1:5173` |
| `ADMIN_PASSWORD_HASH` | Нет default: без него вход администратора отключён, опубликованные ситуации доступны игрокам |

Каталог БД создаётся автоматически. SQLite включает foreign keys, busy timeout 5000 ms и WAL. До готовности сервера применяются миграции **1 → 2 → 3 → 4 → 5**: G0 `foundation_metadata` сохраняется, G2 добавляет `scenario_versions`, `sessions`, `turns`; G6 — отдельную неизменяемую запись `session_preparation` до первого хода. G5 добавляет отдельные context_drafts и context_requests. G8 добавляет principals, отзываемые access sessions, владение попытками и счётчик входа. Миграции 1–4 не изменены. **Старые попытки без владельца сохраняются в БД, но больше не открываются по UUID через API.** При новом запуске игры владелец записывается атомарно; автоматического присвоения старой попытки нет. Startup не очищает данные; неизвестная будущая версия схемы вызывает отказ. Сценарий хранится полностью на сервере и закреплён за сессией; опубликованную версию нельзя обновить или удалить. Повреждённое состояние не исправляется автоматически.

Пароль администратора задаётся через `ADMIN_PASSWORD_HASH`, формат `scrypt$32768$8$1$<salt-hex>$<digest-hex>`. `node scripts/admin-password.mjs` спрашивает пароль без отображения и печатает только хеш. Передайте этот хеш в окружение процесса или локальный игнорируемый `.env`; не коммитьте его. Для автоматизации поддержан `--stdin`: используйте защищённый prompt/secret store, не пишите пароль аргументом или литералом в shell history. Node-команда ниже делает скрытый ввод, сохраняя хеш только в окружении. Изменять execution policy PowerShell не требуется. В памяти процесса пароль кратковременно присутствует; это не защита от компрометации компьютера.

Сессия игрока: idle 24ч, absolute 7д; администратора: idle 30мин, absolute 8ч. Только успешные изменения продлевают idle, максимум раз в 5мин; открытая вкладка и GET ничего не продлевают. Перезапуск с тем же хешем сохраняет ещё действующий доступ; замена/удаление хеша прекращает старый admin-доступ. После выхода, удаления cookie или истечения доступа восстановление старых попыток без аккаунта не предусмотрено. Данные остаются в SQLite; можно начать новую попытку. На вход действует общий для одного узла лимит 10 попыток за 15мин, включая успешные; смена браузера и рестарт его не сбрасывают. Это сознательно простой лимит, возможен временный отказ входа всем администраторам.

Будущий профиль `ACCESS_PROFILE=public` требует `APP_ORIGIN=https://your-host.example`, выставляет `__Host-arena_session; Secure; HttpOnly; SameSite=Strict; Path=/` без Domain. Local использует `arena_session` без Secure и запрещает non-loopback HOST. Локальный HTTP не следует публиковать через tunnel. Реальный HTTPS, доверие к reverse proxy, hosted persistence/backup и clean-machine/public-host smoke ещё требуют отдельной проверки; `PUBLIC_DEPLOYMENT_READY` не заявляется. CORS и forwarded-заголовки не используются как источник доверия.

Каждый ход проходит G1 и сохраняется вместе с ответом в одной immediate-транзакции. Совпадающий requestId и body возвращают прежний ответ; другой body с тем же ID или устаревшая revision дают 409. Невозможная, но корректно заполненная оферта расходует ход и возвращает обычный ответ с отказом. Неверная структура запроса даёт 400, неприменимое действие — 422 без хода. Старый диалог читается из сохранённых текстов. Полная спецификация API и схемы — в G2 receipt.

Драйвер закреплён на **better-sqlite3 12.11.1**, SQLite **3.53.2**. Stable 13.0.3 загрузился при первой установке, но вызвал node-gyp при чистом `npm ci`; разрешённый fallback 12.11.1 прошёл обе установки с официальным Windows prebuilt. Системные build tools не нужны для проверенного пути. Его транзитивный `prebuild-install` выдаёт предупреждение об окончании поддержки; подробности сохранены в receipt.

## Пройти S2 без ключей

В `/admin` выберите **«S2 — Срочная задача и нагрузка»**, нажмите **«Опубликовать S2»** и откройте вход игрока. Сценарий использует тот же движок, SQLite и экран переговоров, что и S1. Обсуждаются объём, срок, помощник и перенос отчёта; сервер проверяет реальную ёмкость и полномочия специалиста.

Путь полной цели: вопрос **«Приоритеты работы»** → **«Доступные ресурсы»** → признать факт о переносе отчёта → аргумент **«Связать помощь с выполнимым планом»** → **полный объём / 2 дня / выделить помощника / перенести отчёт**. Учебная полезность 47 при цели 45. Путь частичного соглашения: ресурсы → признать факт о помощнике → **основной объём / 2 дня / помощник / сохранить срок отчёта** (32). После тех же двух подготовительных ходов **основной объём / 5 дней / без помощника / сохранить срок отчёта** даёт плохую сделку (20 против альтернативы 25). **Полный объём / 2 дня / без ресурсов** физически невозможен и отклоняется; выход сохраняет альтернативу. Итоги объясняются сохранёнными событиями. Отдельный серверный разбор показывает шесть измерений с весами 15/25/20/15/15/10, доказательства и один проверенный следующий фокус. Общий балл требует минимум шесть применимых проверок, три принятых зачёта прогресса и полные обязательные доказательства; иначе — «Недостаточно наблюдений». В старые попытки подготовка не дописывается. Ссылки открывают точную сохранённую фразу из выбранных действий. Сравнение replay показывает общие наблюдаемые проверки только при совместимых версиях; полезность сделки остаётся отдельным результатом.

Для уже собранного изолированного worktree владельца (PowerShell, отдельная demo-БД):

```powershell
Set-Location 'C:\Users\BastaPC\Desktop\Alag-app-work'
& 'C:\Users\BastaPC\Desktop\Alag\.tools\node-v24.21.0-win-x64\node.exe' .\scripts\local-demo.mjs
```

Откройте http://127.0.0.1:3000/admin. Скрипт спросит пароль, если хеш не передан в окружении, и использует `.tmp/owner-app-demo.sqlite`, если DATABASE_PATH не задан. В этой команде Node24 берётся из read-only portable runtime исходного checkout; при установленном Node24 достаточно node scripts/local-demo.mjs. Ctrl+C останавливает сервер. UUID теперь только адрес: доступ требует cookie владельца. Для стабильного admin-доступа между запусками задайте один и тот же ADMIN_PASSWORD_HASH; каждый новый запуск скрытого prompt создаёт новый соль/хеш. Команды обычной установки/сборки выше остаются применимы. Обучение друга остаётся на неизменённом main, application-ветка ему не нужна.
