# AI-related requirements

**CASE REQUIREMENT:** AI допускается/приветствуется (P4 §3.2), но PDF разрешает генерацию **или подбор** сценария (P3, п.2).

**CASE REQUIREMENT:** нельзя оставить жюри с зависимостью от платного API без доступного запасного режима (P4–P5 §3.2); ключи и запуск описываются.

Отсутствие ключа не блокирует этот planning gate и G0–G2. Оно блокирует **будущую сертификацию AI LIVE**, пока не выполнены реальные contract/eval/smoke проверки. Только fallback нельзя объявить завершением AI-first MVP.

# Product requirements

R01–R04, R09, R18 и R22: тренажёр для начинающих закупщиков и руководителей, заказчик — HR/L&D. Ценность: безопасно отработать решение, увидеть его последствия, повторить с другим приёмом; администратор получает новый валидированный кейс из настроек. Эффективность обучения является проверяемой продуктовой гипотезой, а не доказанной метрикой.

В PDF примерами аудитории также служат продажи, HR, предприниматели, закупки и руководство (P2 §1). MVP не обещает одинаковое покрытие всех отраслей; вторичные аудитории и будущие сценарии перечислены в 01.

# Simulation requirements

R05–R10, R21–R22: structured state, скрытые интересы, публичные ограничения, BATNA, переменные сделки, уступки, ветвления и несколько финалов. Формулировка интерпретируется AI; правила дают последствия. Цифровые условия и outcome принадлежат engine.

Обе reference-модели должны поддержать полную цель, частичное соглашение, плохую сделку и отсутствие соглашения. «Отказ» иногда разумнее сделки ниже BATNA; процесс и результат оцениваются отдельно. Replay использует ту же immutable конфигурацию, без переноса знаний в state новой попытки.

# Configurability requirements

R11–R17, R19: сфера, тема, сложность, тон, **роль и цели оппонента** прямо обязательны в PDF. Роль/цели игрока и hard constraints добавлены продуктовым решением и последним запросом. Все настройки входят в snapshot сценария.

Минимальный критерий настоящей настройки: изменение одного поля даёт проверяемый diff в issues/interests/constraints/utility/authority/policy или доступной информации. Простая замена текста prompt не проходит V03. Случайные изменения от повторной генерации не считаются доказательством влияния конкретного поля.
